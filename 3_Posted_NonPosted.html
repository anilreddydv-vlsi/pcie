TLP header fields
Posted: fire and forget
Requester sends the TLP and no Completion comes back.
• Memory Write (MWr)
• Messages (Msg / MsgD)
Fast: no waiting and no tag held. A DLL ACK only proves the TLP crossed one link, not that it reached the target.
Non-Posted: needs a Completion
Requester waits for a Cpl / CplD matched by Requester ID + Tag.
• Memory Read (MRd), Locked Read
• IO Read / IO Write
• Config Read / Config Write
• AtomicOps (FetchAdd, Swap, CAS)
Even IO/Config writes are non-posted: they get a Cpl with no data.
Routing
Memory/IO requests (MRd, MWr): address routing using the switch's Base/Limit windows.
Config requests: ID routing (by Bus/Device/Function).
Completions: ID routing using the Requester ID's bus number against each port's secondary–subordinate bus range.
Per-link vs end-to-end
Seq# + LCRC (DLL) are per-link. Each switch checks them, ACKs, then puts a new Seq#/LCRC on the next link.
TLP header (TL) travels end-to-end, unchanged.
Flow-control credits
The receiver keeps separate buffers for Posted (PH/PD), Non-Posted (NPH/NPD) and Completion (CplH/CplD) TLPs and advertises credits for each with UpdateFC DLLPs. A transmitter's Transaction Layer may send a TLP only if the receiver has credits of that type. Keeping them separate is also what lets ordering rules allow posted writes to pass stalled non-posted requests, which avoids deadlock.
